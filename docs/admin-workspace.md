# Admin workspace improvements

The management dashboard now has an action center backed by `GET /api/admin/workspace`: unread incoming messages, conversations waiting for a reply, standard service requests without a later admin reply, and stored unpublished services/testimonials/products/demos. Counts cover the full tables; the action lists show a bounded recent subset. Draft links open the corresponding editor, and reply links can open a conversation even when it is not in the first page of the list. Unpublished database content is distinct from unsaved form edits.

Generic CRUD management pages open on their searchable, state-filtered, paginated list (20 rows), with safe image/icon thumbnails and native disclosure menus for row actions. Add/edit opens the editor. Service editing has Basics, Appearance, Details and Publishing groups, direct section links and a sticky save bar. Existing entity payload contracts are retained. Search/filter state remains while editing and reloading the list.

`admin-workspace.js` supplies in-memory dirty tracking, a small unsaved-state label, beforeunload protection and confirmation before discarding/navigating away. No draft-management block or new browser-stored content draft is added. Generic CRUD forms, product/demo editors and profile/password forms use this helper. Confirmed successful saves clear dirty state; failed saves retain content. Server field errors and client publishing/price checks appear next to their controls with invalid/described-by semantics. The existing profile refresh no longer overwrites a dirty profile editor. Passwords are not persisted by this feature.

The media library includes SVG uploads, SVG/image/document and in-use/unused filters, links to referencing content and quick links to use a vector for a new skill/service. `GET /api/media/usage` tracks structured project/service/skill/statistic/profile/testimonial references and product cover IDs. DELETE rechecks references on the server and returns 409 for an in-use media ID. SVG replacement uses the same sanitizer as SVG upload. Byte-identical uploads of the same media type reuse an existing file, while different content with the same name remains separate. Deduplication does not rename the existing file. These checks cover structured database references, not arbitrary links embedded in external/static documents; string references are not newly converted to database foreign keys. This is an application-level safeguard, not a distributed upload uniqueness or concurrent reference-locking guarantee.

Admin conversations now support server-wide paginated search and filters. NEW means unread incoming messages; WAITING means the latest message is from the client (and can include NEW); HANDLED means the last message is from admin with no unread incoming messages. Reading and replying update these derived states through existing message data. HANDLED indicates a reply, not a manually closed ticket. Out-of-order search results are discarded, and search controls are locked during sending. Selected conversation and numeric scroll positions are scoped to the admin account, with per-conversation restoration. No message text is copied into this preference storage.

All new workspace, usage and direct-conversation endpoints retain admin-only access through the existing security configuration and method authorization. There are no new tables, migrations, external services or dependencies. Shared admin styles use self-hosted Estedad, the existing emerald palette, visible focus, mobile controls and reduced-motion behavior. Public page layouts and public chat actions are preserved.

- `check-admin-workspace-browser.cjs`: action links/deep editing, list search/filter/paging, service groups, dirty-state cancel/confirm, inline errors, media usage/delete lock and conversation search/scroll restoration. Uses isolated API fixtures and no screenshots.
- `check-admin-workspace-api.py`: actual anonymous/regular-user rejection and admin-only endpoints, stored draft links and NEW → WAITING → HANDLED transitions using owned fixtures. Requires a disposable local PostgreSQL app and `HEXORA_TEST_DB_FIXTURES=1`; cleans its inserted messages, service and ordinary test account.
- SVG integration checks verify persisted names, deduplication, protected deletion and theme-colored public rendering. Shared UX checks cover public chat drafts and account separation.
